# Security Policy

## Supported Versions

0GP Race is currently in active development.

Security fixes will be applied to the latest development version of the plugin and related services.

| Version | Supported |
| --- | --- |
| Latest development version | Yes |
| Older development versions | No |

---

## Reporting a Security Issue

If you discover a security issue affecting 0GP Race, please do not publicly disclose exploit details before the issue can be reviewed.

Examples include:

- Ways to falsify race scores
- Ways to bypass imported-item or bank protections
- Multiplayer room spoofing
- Server or API vulnerabilities
- Exposure of player data
- Authentication or session weaknesses
- Malicious input that could affect other racers
- Any issue that could compromise race integrity

Please report the issue directly to the project maintainer.

GitHub:
https://github.com/Hottestganga/kaha-0gp-challenge

When reporting an issue, please include:

- A clear description of the vulnerability
- Steps required to reproduce it
- The affected plugin or server version
- Any relevant screenshots or logs
- The potential impact

---

## Player Data

0GP Race is designed to collect only the information required to operate races and multiplayer features.

Depending on the feature in use, this may include:

- RuneScape player name
- Race room code
- Race score
- Race status
- Remaining race time
- Race transactions required for scoring or verification

0GP Race does not require RuneScape account passwords or Jagex account credentials.

Players should never provide account passwords, authentication codes or Jagex account credentials to 0GP Race.

---

## Third-Party Services

Online multiplayer and website functionality may communicate with infrastructure operated by the 0GP Race project.

The RuneLite plugin will clearly identify any information transmitted to external services.

---

## Race Integrity

The scoring and transaction systems are designed to reduce cheating and accidental score manipulation.

However, 0GP Race is community software and no anti-cheat system should be considered perfect.

Suspected exploits should be reported so they can be investigated and corrected.

---

## Responsible Disclosure

Please allow reasonable time for a vulnerability to be investigated and fixed before publicly sharing technical exploit details.

Responsible reports are greatly appreciated.
